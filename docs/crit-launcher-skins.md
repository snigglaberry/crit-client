# Crit Launcher skin handoff (v1)

This works with Crit Client **v2** builds that declare `custom["critclient:launcher_skin_bridge"] = 1` in `fabric.mod.json`. It does not require a Java API call, a server, a skin library import, or CustomSkinLoader on a Crit Client instance.

## Contract

- **Launch:** put exactly one `-Dcritclient.launcher.accountType=offline`, `=microsoft`, or `=ely` before Minecraft's main class, using the actual account passed to `build_launch_command`. Keep the normal `--username`, `--uuid`, `--accessToken`, and `--gameDir` arguments. For an offline account this means the launcher's normal offline UUID and token `0`. For a managed launch, `Sessions.applySavedOnce()` keeps the launcher's account; it does not clear the mod's saved account choice or prevent manual switches later. Without this JVM property, standalone account selection works as before.
- **Apply an offline skin:** write UTF-8 JSON atomically at `<gameDir>/config/skinstudio/offline-skins/<uuid>.json`. Use the launched account's UUID as lower-case, hyphenated text. The skin is plain standard base64 of the PNG bytes, **not** a `data:` URL. Valid skin sizes are `64×64` and `64×32` (legacy, always classic). A PNG is limited to 200,000 bytes and the JSON to 280,000 bytes.

  ```json
  {"version":1,"variant":"slim","png":"<base64 PNG>"}
  ```

- **Reset:** replace the same file with `{"version":1,"png":null}`. Absence means no selection. Do not delete the file to signal an explicit reset. Crit Client keeps its older `offline-skin.*` files for standalone migration, but does not use them on a managed launch. Missing, malformed, or unsupported files leave the vanilla skin in place.
- **Read back:** Crit Client writes the same format when applying or resetting from its Skins page. It may add a `clientKey` for its own gallery highlight; launchers should ignore it when reading and omit it when writing a replacement. The launcher should render `variant` from the shared file rather than guessing it from alpha.
- **When:** Crit Client reads the file on boot (`CLIENT_STARTED` → `Sessions.applySavedOnce()` → `OfflineSkin.load(boolean migrateLegacy)`) and when switching accounts in-game. It decodes once and uses the same pixels for the title screen and the in-game texture. Changes from within Crit Client apply immediately. Launcher changes take effect at the next launch or when switching back to that account in-game; there is no live file watcher. This protocol is for **offline skin bodies only**; it does not sync libraries or supply capes. Microsoft and Ely.by still use their own account/profile paths.

## Copy/paste prompt for the launcher repo

Implement the Crit Launcher side of the Crit Client v2 offline-skin bridge. Do not edit Crit Client. **Use Crit Client's built-in loader whenever Crit Client is enabled; retain CustomSkinLoader (CSL) in all other compatible instances.** Implement both Windows and Linux front ends.

1. **Detect the backend locally** in `crit_launcher/addons/critclient.py` by reusing `_client_jars(instance_mods_dir(name))`. The Fabric mod ID is `critclient`; bridge support is integer `1` at `custom["critclient:launcher_skin_bridge"]` in the JAR’s `fabric.mod.json`. Do not use the filename, release status, or stored UI badge. Ignore parked and `.jar.disabled` mods. An old Crit JAR is never a CSL target: report “Update Crit Client to use launcher skins.” If both mods are enabled, report the conflict and point to the existing mod-toggle UI; do not silently remove or replace either. With no enabled Crit Client, keep CSL for supported Fabric, Forge and NeoForge versions. Reuse `_find_version(CSL_PROJECT, loader, mc_version)` to check the exact loader and game version before offering an install. Vanilla, Bedrock and Horizon aren't local-skin targets.

2. **Read and write the bridge file** in `crit_launcher/skins/critclient_bridge.py`. Add `read_local_skin(instance_name, account_uuid)` and `write_local_skin(instance_name, account_uuid, png, variant="classic")`. The path is `instance_config_dir(instance_name) / "skinstudio" / "offline-skins" / f"{uuid.UUID(str(account_uuid))}.json"`. Write UTF-8 JSON through a unique temp file in the same directory and `os.replace`:

   ```python
   # png is validated PNG bytes, or None for reset
   payload = {"version": 1, "png": None}
   if png is not None:
       payload.update(variant=variant, png=base64.b64encode(png).decode("ascii"))
   ```

   Validate with the existing `decode_png_uri(image)` on apply: `64×64` or `64×32`, max 200,000 bytes. Allow only `classic`/`slim` and force `64×32` to `classic`. On read, validate version, schema, base64 and size (max 280,000 JSON bytes) and ignore `clientKey`. Return `None` for missing/invalid data; otherwise return `{ "png": bytes_or_None, "variant": variant_or_None }`, so a valid reset is distinct from a missing file. Store no credentials, paths or URLs.

3. **Route apply and reset** in `crit_launcher/skins/api_local.py`. Use its `uuid` for the Crit file and validated `name` for CSL. Both sides derive offline UUIDs from the case-sensitive `OfflinePlayer:<username>` string; reuse the stored UUID rather than regenerating it. Extend `local_set_skin(image, install=None, variant="classic")`: for each bridge-ready instance write directly with `downloaded=False`, no Modrinth request, and no CSL setup or first run. Preserve `_local_bulk()` / `_csl_ensure()` / `_csl_local_dir()` for non-Crit instances with CSL installed or selected for install, including `CustomSkinLoader/LocalSkin/skins/<username>.png` and the first-run check. Check for enabled Crit Client before `_csl_ensure()` in the direct `local_install_csl(instance_name)` endpoint too; this guard applies even to an old Crit JAR. In `local_use_ely(name=None)`, pass the returned `skin["variant"]` through the same apply path, without resolving the target account again after the lookup. In `local_reset()`, write `{"version":1,"png":null}` on Crit targets; keep the CSL reset on CSL targets and make sure its old `SKINS_DIR/<username>.png` cache cannot revive a reset. Preserve `{success, results:[{name, ok, downloaded, error?}]}`.
